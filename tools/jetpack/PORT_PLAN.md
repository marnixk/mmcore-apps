# Jetpack mmcore port plan (phase 1 proposal)

## Target resolutions

House targets (see `tools/gametest/modes.txt`):

| Profile | Mode | Physical | Art canvas (`lay.aw`×`lay.ah`) | Scale `sc` |
|---------|------|----------|----------------------------------|------------|
| Chromebook / low | **MODE 20** | **683×384** | 683×384 | 1 |
| Chromebook hi | MODE 19 | 1366×768 | 683×384 | 2 |
| HD 16:9 | MODE 11 | **1280×720** | 640×360 | 2 |
| Full HD | MODE 16 | 1920×1080 | 640×360 | 3 |
| 4:3 | MODE 1 | 800×600 | 400×300 | 2 |

**Note:** Marnix asked for a gameplay mockup at **683×384** aligned with the Chromebook **MODE 19 art size** (683×384 logical pixels). In this repo MODE 19 is 1366×768 with `sc=2`; MODE 20 is native 683×384.

Original playfield is **624×384** px (26×24 by 16×24). All targets **letterbox or pad** to full screen—no small bordered “window”.

### Layout adaptation (no extra mockups)

| Resolution | Playfield scaling | HUD |
|------------|-------------------|-----|
| **683×384** | Integer tile scale **1** (native 24 px tiles); ~**29 px** side margin each side for fuel/gems/level text | Single thin bar (level, gem count, fuel gauge) |
| **1280×720** | Tile scale **2** (48 px) → 1248×768 content; **vertically centered** with slim top/bottom bars | Same HUD, larger glyphs via `sc` |
| **1366×768 (MODE 19)** | Same art as 683×384 with `sc=2` | Identical layout to MODE 20, pixel-doubled |
| **1920×1080** | Art 640×360, `sc=3` → 1248×768 field centered | Wider side gutters for HUD |
| **800×600** | Art 400×300, `sc=2`; field ~832×512 max—use **scale 1** tiles (24 px) centered | Compact HUD |

## Graphics scaling

- Source tiles/sprites: **24×24**, 256-colour VGA palette (`JETPAL.DAT`).
- Phase 2: nearest-neighbour upscale by `lay.sc` for crisp retro look (matches other repo games).
- Phase 1 previews use **editor palette** flat tiles; final port uses decoded sprite sheets from `JETPACK*.DAT`.

## Drawing strategy

- **Back page** + dirty rectangles (house standard).
- **Static tiles:** mark dirty on phase state change, gem pickup, barrier toggle.
- **Sprites:** player, enemies, projectiles—blit from sheets; union dirty rects per entity (24×24 or larger for jetpack flame frames).
- Full-screen blit via existing `scr.present()` pattern (see `games/voidrunner`).

## Input

```text
ON KEY: arrows, ALT (jet), CTRL (phase), DOWN (action)
SETTICK: read held state each frame for movement/thrust
Menus: INKEY$ only
Pause: P or Esc → pause dialog; Q → title
```

Map Alt/Ctrl to the same logical actions as DOS; no joystick in phase 2 unless requested.

## Audio

**Silent by default** (house rule). `JETSOUND.DAT` extraction optional later.

## Pi 400 risks

| Risk | Mitigation |
|------|------------|
| Many moving enemies (up to 20 slots) | Cap dirty rects; simple AI tables; avoid `LOCAL` in tick |
| Phase tile animation timers | Global arrays for tile states; batch redraws |
| 26×16 tile updates | Only redraw changed cells |
| 5 resolutions | Generated `layouts.inc` from script; one art sheet per scale |
